# 個人 AI 助理的 IIS 網頁

ASP.NET Core .NET 10、本機 IIS、HTML 介面。站台使用 127.0.0.1:18765，模型和 SQLite 保存在 F 槽個人助理專案。

- 開機後首次開啟桌面捷徑時，使用模型和訓練都關閉。
- 頁首可選擇 Qwen3.8-27B BF16、Qwen3.8-27B Q8_0 或 Qwen3-4B BF16，並查看每輪輸入和輸出的 token 上限。Q8_0 的上下文為 16,384 tokens，每輪輸入最多 15,868 tokens，回覆最多 512 tokens。選擇會保存在本機，開關維持原來狀態。輸入額度含系統提示與帶入的對話，本機運行沒有服務商每日額度。
- Q8_0 用於聊天，LoRA 微調及候選仍使用 BF16。重新安裝時，把釘選的 Q8_0 GGUF 放入核心專案的 `data/learning/experiments/qwen38-bf16-rtx5080/chat-q8`，在核心目錄執行 `.\.venv\Scripts\python.exe -m scripts.learning.verify_qwen27_q8`，完成 SHA-256 核對後重新整理網頁。[Q8_0 權重版本](https://huggingface.co/bartowski/Qwen3.8-27B-GGUF/blob/419d4bf0b4841d3517a2a15a70465abdf655281c/Qwen3.8-27B-Q8_0.gguf)
- 開啟「使用模型」後可聊天。開啟「訓練」後，選確認更正和未見驗收問答，再安排閒置微調。
- 重新開啟「本機模型學習」可查看上次中斷的階段。仍有效的已確認更正可選入新批次。
- 微調前後的驗收共用目前 27B 網頁聊天設定。舊批次仍可查看，適配器需通過目前設定的驗收才可選用。
- 候選使用的更正撤回或改版後，學習清單會標出來源變更。如果該候選是目前選用版本，可切回 BF16 底座或選另一個仍可用的模型。
- 只有使用者親手在 IIS 頁面開啟對應模式，再從該頁面送出工作，才授權載入模型或開始訓練。執行入口會在載入權重前核對授權。
- 切換或關閉會強制終止目前工作的 Windows 程序樹，確認退出後才切換狀態。聊天和 27B 微調共用 GPU 鎖。
- 對話保存在既有 SQLite sessions 和 messages。你可把所選對話移到回收筒，還原或永久刪除該對話的主資料庫聊天內容及回答紀錄。匯出檔案、備份、記憶、另存的學習例子與自主工作保有自己的保存範圍。
- 長對話向上捲動後，可按「載入更早訊息」逐頁查閱，仍停在原本閱讀的位置。
- 每則回答旁會顯示已記錄的模型或本機工具。點開模型名稱可查底座版本及 LoRA 批次。舊紀錄若只保存當時的選擇，會顯示「當時選用」。
- 模型回報完整用量時，展開回答來源可查看實際輸入與輸出 token 數。輸入含系統指引及帶入的對話。
- 超過輸入額度時會顯示分詞後的實際數量與本輪上限。4B 先用已核對的分詞檔檢查，通過後才驗證並載入權重。
- 各段對話的未送出草稿自動存到本機 SQLite。看到「草稿已存本機」後，即可切換對話或重新整理。另一個視窗已保存新版時，由「核對草稿」選擇要保留的內容。
- 訊息入庫後會顯示「訊息已送出」。模型回答期間可先編輯下一則草稿，等本輪結束後再送出。
- 回答時會顯示核對設定、啟動、載入、分詞和生成等目前階段，以及階段與整輪的耗時。取消或失敗時可查看最後的階段。 完成後展開回答來源即可查看各階段耗時。最後一筆未完成的問題下方也可查看本輪耗時。
- 27B 的載入階段會顯示執行器已回報的權重載入百分比。權重載入完成後，會等模型就緒才進入分詞。
- 已送出但未完成的最後一題會標示可重試。按「重試上輪」時會核對畫面上的題目，若另一個視窗已改變對話，需先看更新內容再重試。
- 更正表單送出時會核對你開啟時看到的版本。若另一個視窗已更新或撤回該項目，可先比對本機版本，再決定是否再次確認。
- 桌面捷徑會在預設瀏覽器建立本次連線。同一瀏覽器可重新整理或用新分頁開啟，頁首顯示兩個開關的目前狀態。
- IIS 頁面和桌面橋接負責顯示歷史與控制狀態。兩個開關都關閉時會釋放 Qwen 推理及訓練程序的資源。
- 有自主工作仍依賴原聊天來源時，這段歷史可留在回收筒。保留或移除由使用者選擇。

在專案根目錄執行 dotnet publish -c Release -o deploy，再以系統管理員執行 Deploy-Iis.ps1。桌面捷徑執行 Open-Desktop.ps1，讓 GPU 作業與 Windows 閒置偵測在登入工作階段執行。[Microsoft Learn 的 IIS 部署說明](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/iis/?view=aspnetcore-10.0)

程式保存在 F 槽本機 Git。runtime、deploy、資料庫、對話、模型權重、適配器和桌面連線金鑰都由 Git 忽略。

## 接入現有個人助理

網站維持獨立專案，桌面橋接沿用原助理的 SQLite、確認佇列與模型環境。`bridge/assistant-core.patch` 保存這次接入原助理的程式碼，二進位執行環境和權重沿用 F 槽的已安裝版本。相容基線為原助理提交 `3cd62d0adc2c1b72b5afa4b14fb842658f8b8b0e`。在相容的原助理 checkout 先以 `git apply --check` 驗證這份補丁。有了接入後的版本，即可在同一 Windows 登入工作階段從桌面啟動網站。
